Handshake, safety numbers and multi-device behavior

Session setup: four X25519 agreements combine identity, ephemeral, signed-prekey and one-time-prekey material. Hybrid peers also mix in ML-KEM-768. HKDF derives the root and initial message key. Later messages use the Double Ratchet; bounded skipped keys support reordering.

Identity checks: users can compare safety numbers. Account-key changes clear verification; authenticated suite downgrades are rejected. Every recipient device gets its own session and encrypted copy, including encrypted self-sync to the sender’s linked devices.

Group key limits, replay handling and protocol status

Epoch boundary: keys derive from the epoch secret with per-sender and per-generation inputs. Compromising that secret exposes derivable content keys within that epoch; this is not the direct-message Double Ratchet. Membership updates establish a new epoch secret.

Receive behavior: signature failures, stale epochs and replays are rejected. Future epochs and storage failures stay unacknowledged for retry. Generations must exceed the last accepted value for that sender, so older out-of-order group messages are not recovered. This is a custom construction, not RFC 9420 wire-compatible MLS.

This is a development implementation, not a production-security claim. Hybrid and group releases require internal verification of the exact candidate; independent review is additional scrutiny. Endpoint compromise and traffic correlation remain risks. Privacy-edge separation also depends on restricted internal delivery routes.
