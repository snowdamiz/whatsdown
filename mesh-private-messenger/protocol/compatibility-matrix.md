# Compatibility Matrix

| Feature | Wire/version identifier | Persistence | Compatibility rule | Production status |
|---|---|---|---|---|
| Classical one-to-one | protocol `1`, suite `0x0001` | ratchet snapshot `2`; `1` is read, without its skipped keys, and rewritten as `2` | Authenticate the selected suite; reject unknown mandatory extensions and downgrade below the strongest observed suite | Reachable; exact-candidate internal verification required |
| Hybrid one-to-one | protocol `1`, suite `0x0002` | ratchet snapshot `2`; `1` is read, without its skipped keys, and rewritten as `2` | Explicit negotiation only; classical fallback is permitted only when the authenticated peer does not advertise hybrid support | Reachable experimental construction; internal verification required |
| Group messaging | commits `1`/`2`, messages `1`/`2`/`3`/`4`, recipient transport `SGP` `1`, suite `0x0003` | group snapshots `1`/`2`, storage purposes `12`, `16` and `17` | New groups use state/commit `2` and recipient-wrapped messages `4`; legacy reads retain their original semantics; authenticated epoch transition required for upgrade; reject downgrade | Reachable custom protocol; internal verification required; not RFC 9420 wire-compatible |
| Attachments | attachment wire `1` | none; hosts persist only sealed manifests and chunks | Reject changed manifests, wrong chunk indices, non-canonical sizes, oversized input, and trailing bytes | Development only; streaming mobile and object-store integration required |
| Encrypted backups | backup wire/profile `1`, Argon2id v1.3 | opaque sealed manifest and chunks only | Parameters are fixed per version; reject changed profiles, manifests, chunk order, snapshot hash, oversized input, and trailing bytes | Development only; opt-in mobile restore and opaque backup storage required |
| Push provider tokens | sealed-token and broker-wake wire `1` | directory stores only broker-sealed ciphertext | Only the configured broker key can open a provider token; reject unsupported providers, malformed tokens, tampering, oversized input, and trailing bytes | Development only; production provider adapter and mobile registration required |
| Directory and delivery | delivery wire `1` | migrations `001`–`010` | Clients and services reject unsupported versions and trailing data | Development only |
| Recipient-sealed transport | `RCP` version `1`, outer suite `4`, ratchet message `3` | none; envelopes are opaque to delivery (migration `012`) | New sends always sealed; suite and packet shape must agree; legacy `SIP`/`SGP`/bare packets stay readable, a bare initial packet never is | Development only; update all clients together |
| Direct client transport | `M8P` version `1`, kinds `1` and `2` | inside sealed session/outbox records | CLI and mobile use the same canonical codec and session-bound ratchet AAD; reject wrong kinds, trailing data, identity/session mismatches, and suite mismatches | Development only; Mesh CLI/mobile suite-2 interoperability proof required |
| Mobile native ABI | `MESH_LIBRARY_ABI_VERSION = 1` | encrypted record format `1` | Host and generated bindings must use the same ABI; private keys never cross into TypeScript; displayed plaintext does | Physical iOS and Android proof required |

Persisted records and wire messages always carry their existing version. An incompatible field, algorithm, domain label, or canonical encoding requires a new version; it must not silently reinterpret version `1`. Database migrations are forward-only. Rollback is allowed only while the target revision understands every deployed migration, protocol version, suite, snapshot, and native ABI.

CI pins the exact Mesh revision used by Morse. Updating that revision requires protocol, persistence, native-binding, downgrade, and mobile proof reruns before merge.

The earlier private, unversioned mobile direct-message wrapper existed only in development and was never deployed or accepted by a production service. It is retired in favor of canonical `M8P` version `1`; there is intentionally no legacy decoder for that undeployed format.
