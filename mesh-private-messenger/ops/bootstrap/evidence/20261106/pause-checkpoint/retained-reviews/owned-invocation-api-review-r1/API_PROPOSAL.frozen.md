# R2 direct scheduled invocation proposal (before public API edits)
Base 9b844dbab34e61f6de575af2b25b0ed0f321059e. R1 header remains byte-identical.

## Native C surface
New separate generated header fragment, with opaque `MeshOwnedInvocationV2`.
Each existing logical export `name` additionally generates a native-only companion:
`int32_t name_submit_v2(const MeshNativeAuthority *, const uint8_t *, uint64_t, MeshOwnedInvocationV2 **);`
The compiler companion directly supplies the private lowered entrypoint and its existing max input/output constants to runtime `mesh_library_submit_bounded_v2`. It never calls the synchronous export wrapper. Manifest metadata adds `scheduledSymbol` to the SAME logical export, with unchanged audience and limits. JS bindings unchanged. Trusted native adapter validates/narrows original module/export descriptor + audience + allowed operation before selecting the companion fnptr. Request bytes cannot select it. New runtime entry is not a serialized-request dispatcher.

`int32_t mesh_library_invocation_take_v2(MeshOwnedInvocationV2 *, MeshLibraryBytes *);`
Returns PENDING=12 until root finalization, then root status (0, fixed application error9, refused10, panic4, existing size/error statuses); consumes result exactly once; further takes return TAKEN=13. Output uses existing free_returned_bytes. Successful result bytes remain private native output, not an effect/publication permit. No raw protected error bytes.
`int32_t mesh_library_invocation_cancel_v2(MeshOwnedInvocationV2 *);`
Monotonically refuses this invocation; marks its original local processes for termination and wakes workers; never retires unrelated generation or waits for HTTP. Already admitted finite work may complete; later attempts refuse. No cleanup effect grant.
`void mesh_library_invocation_release_v2(MeshOwnedInvocationV2 *);`
Releases caller ownership, does not implicitly cancel or join. Process/descendant/worker owners keep original context. Standard native references: no concurrent release/use of same reference.

No completion callback is needed in this first unit: nonblocking take observes an owned completion; no host drive/materialize API. Submission success means lifetime acceptance only, not execution/effect permission. Nested submission/calls from Host or Mesh frames refuse BUSY to prevent native callback reentry/borrowed-stack escape. Input copied before return and bounded before allocation. No JNIEnv, stack frame or borrowed caller buffer crosses submit. Native Host callbacks run on original scheduler worker native stack and retain V2 context; adapters must use JavaVM attach + retained global refs, never captured JNIEnv. Real JNI integration remains a separate platform gate.

## Ownership and scheduler
An actual Scheduler Process gets its own PID, coroutine/yielder/GC stack, original InvocationContext, library heap ownership, and Arc-owned input/completion before enqueue. One existing scheduler lane is sufficient; HTTP uses existing cooperative wake channel. No parking of CallContext, and CALL_LOCK remains on the legacy sync API. Scheduled companion bypasses that wrapper only after the same-fixture held HTTP/fresh status-load red/green proves progress. Native serializers untouched.

Root completion is after root termination/resource cleanup; it does NOT claim descendants or already accepted HTTP settled. Descendants retain original authority/Host and borrowed heaps independently of result consumption/release. Cancellation and forced termination finish completion exactly once even before first resume. Coroutine drop must unwind with original TLS context; HTTP pending registry uses cancellation/drop cleanup. Output is zeroized on drop/refusal; take checks original retirement again but grants no publication permission. Root results retain context until handle release; stale take wipes bytes.

Every later effect uses R1 admission on immutable original nodes. Resume must never substitute current/global Host. Transaction/resource ownership guard refuses and unwinds suspend-capable work before parking. Callback SQL transactions and per-statement admission preserved. Root-owned SQLite handles may survive permitted external waits only with no open transaction and same original owner.

## Parent clarification / API HOLD
Public header, generated native companions and manifest API edits are on HOLD pending fresh parent API review mesh-owned-invocation-api-review-20261106-r1. Nonpublic prototype and baseline continue. The future companion design ADDS physical native C symbols. It preserves the 176 logical Mesh operations, their legacy ABI symbols, audiences, request/response limits, and JS routing; it does not claim exactly176 physical symbols. Verify both generated and actual app manifest consumers do not enumerate companions as public operations.

Submit holds lifecycle mutex only across checking Running and inserting/enqueueing fully owned process, so shutdown cannot race new work into an already stopped scheduler. Calls before init/after shutdown refuse2 and return null handle. Invalid inputs/limits refuse before ownership; internal queue construction must either publish process+handle together or unwind and release all ownership. Root finalization makes output Ready; take under completion mutex transfers once. Concurrent cancel/take linearizes at completion lock: cancel-first discards pending result/refuses; take-first can transfer exactly original native bytes, with no claim about later publication. Cancellation atomically refuses before scheduling termination, but never forcibly interrupts an executing finite effect: worker owns coroutine, and termination takes effect only at its next safe point; no arbitrary thread unwinding. Native caller release never joins or cancels. Shutdown is explicit joining API (not retirement/cancel); outstanding caller handles stay valid for observing their terminal result/releasing it after runtime stop. Accepted HTTP workers may outlive cancellation/root completion; they retain context until actual worker exit. External real JNI/native serializer proof remains separate.
