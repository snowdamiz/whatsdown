**N1 scenario and concurrency assessment.** Let H be a live handle with a Ready success, with its sole caller reference retained and release excluded. An operation callback attempting `take(H, &empty)` receives3, leaves the output empty and leaves H Ready; a later ordinary take can still consume that result. A callback attempting `cancel(H)` receives3 without setting refusal, requesting termination or replacing the outcome. The same preservation rule covers Pending and Taken. `take(NULL, &empty)`, `take(H, NULL)` and `cancel(NULL)` receive1 even in callback context; the valid destination is cleared where present. These outcomes are now determined without acquiring the completion/process lock. Concurrent permitted callers may independently advance H; “unchanged” describes the rejected call's effect, not a freeze of other actors.

Ordinary permitted cancel still returns0 repeatedly, preserves Pending until actual root cleanup, replaces Ready with refusal10 and cannot recreate a Taken result. Cancellation and take arbitrate under the same completion mutex; original generation retirement uses the retained monotone scan. No early rejection becomes a terminal take, no callback rejection silently cancels work, and no post-transfer cancellation claims to recall bytes. Empty-output clearing is compatible with the explicit empty-destination obligation; it does not free unrelated memory. The release restriction is a native caller obligation, not an invented BUSY return from a void function. Null release remains a no-op. These changes close the exact round-two conflict without changing ownership or adding an authorization mechanism.

**Retained lifetime and shutdown decision.** Proposal line64 requires generated module, runtime and registered operation/lifetime callback code to stay loaded until process exit from first scheduled use, including retained dlopen handles. Neither shutdown nor Host context release permits unloading. Lines66–70 permit last-context release on native callers, scheduler workers, delayed timer threads or detached HTTP workers, including after shutdown, subject to bounded, thread-safe, nonjoining, non-unwinding cleanup. Owned deferred native disposal must retain its data and target an executor that remains available through disposal. JSI objects and borrowed JNIEnv/stack pointers remain excluded.

This rule addresses the actual pinned boundaries: [authority.rs:52](pinned/compiler/mesh-rt/src/authority.rs#L52) directly calls foreign release on final drop; [stack.rs:119](pinned/compiler/mesh-rt/src/actor/stack.rs#L119) supplies the operation native-stack mechanism; [http/client.rs:848](pinned/compiler/mesh-rt/src/http/client.rs#L848) retains the original invocation in a detached worker; [scheduler.rs:418](pinned/compiler/mesh-rt/src/actor/scheduler.rs#L418) joins scheduler workers. Amendment3 requires the missing disposal marker/stack coverage and releases LIFECYCLE before finalization/join/foreign disposal. Ownership capable of foreign release must be detached under lifecycle/completion/process-table/process locks and disposed after unlocking. Root Ready remains after cleanup.

For a cancelled root whose admitted HTTP continues beyond shutdown, the HTTP owner retains the original Host until actual completion; process-lifetime code pinning keeps its execution and eventual release callback callable. A remaining invocation handle can still be taken/released after stop, and successful returned bytes remain independently owned until the existing runtime free function wipes them using private allocation length ([library.rs:536](pinned/compiler/mesh-rt/src/library.rs#L536),573–589). Shutdown may still block for legacy calls and scheduler-owned roots; it is not a cancellation, local-settlement, native-replacement or HTTP-quiescence primitive. These are usable, restrictive embedding obligations. No additional unload API is necessary for this bounded design.
