# Explicit read-only CLI v2 bond selection

The command supports `morse bonds --log LOG_NAME --v2-config FILE`. The existing `morse bonds --log LOG_NAME` keeps its exact legacy parser, SecurityConfig/environment pins, reader and output. `MORSE_BOND_LOG_VERSION` continues to select the log format; it is not a collateral-version switch. No failed legacy read selects v2, and no failed v2 read falls back to legacy.

The explicit v2 file uses the existing public-chain schema1 outer object (`scope`, `pins`, `endpoints`, `minimum_context_slot`, `max_age_seconds`) and its complete schema2 `collateral` selection. See `ops/public-chain/README.md` for the canonical shape. The outer token program/governance/code-slot/USDC pins and all collateral judge/rewards/log/service/MORSE/start/witness pins are required. Three canonical distinct origins are mandatory; configured mode requires HTTPS, while explicitly labeled local-fixture mode accepts owned loopback HTTP. There is no provider discovery or independence inference. The command reads only the bond selection, ignoring burn epochs/history and proof selection; the compatible outer treasury/factory fields do not cause a burn or treasury read.

Mesh derives all expected PDA/account roles, validates a single bounded finalized account batch per origin, and requires two identical whole-bank digests. Account order, actual absence, owner, metadata, full lengths, log/service/witness identity, token binding/config/pool, both six-decimal mints, vault custody, tracked principal/pending and donation accounting remain in the canonical protocol readers. Every selected bond must be MBD2 inside MEC2, with all three configured release slots current. This intentionally narrower CLI policy matches the public report adapter. The native counter separately supports explicitly authenticated migrated MBD1 USDC under MEC2; that protocol support is not removed by this CLI selection rule.

The output uses decimal strings and an asset/mint per row. Principal, recorded pending, effective pending liability, actual selected vault balance and donation surplus stay distinct. Opposite-asset vaults are separate nullable observations. There is no cross-asset sum, dollar peg, current token price or inferred complete/global custody total. A recorded pending target is program metadata, not an authenticated current valuation. Missing/invalid/disagreed/stale/future/wrong-release observations print no balance report and exit1. The CLI samples its real host clock; configuration-supplied report timestamps cannot override it. Maximum permitted age is an explicit canonical1..86400-second input.

## Qualification

The command, parser, tests and fresh-bank fixture are adopted in this checkout. The original guarded delivery and frozen compiler/runtime inputs are retained in `.morse/witness-proof/bonds-v2-cli/manifest.json` at repository root. There is no signer, deposit, transaction builder/submission, writer, scheduler, reward keeper, public release or activation path.

The new Mesh parser test is self-contained and covers the public schema, exact large U64 minimum slot, selection binding, bounds and refusal before I/O. Existing legacy bond/receipt tests remain. `scripts/bonds-v2-command.test.mjs` always checks explicit mode/schema refusal and optionally executes the fresh owned-bank suite when `MORSE_CLI_BIN` and `MORSE_BONDS_V2_FIXTURES` are provided. `MORSE_BONDS_V2_HISTORY` selects the committed historical corpus for an additional stale refusal. The existing bonds command test accepts an explicitly prebuilt CLI so both paths can use one exact candidate executable.

A test-only `fresh_readonly_bonds_v2_snapshots` extension of the existing Rust custody harness preserves ordinary `TokenHarness::new()` behavior and accepts an explicit host sample only for a new owned SBF bank. It aligns the initial historical oracle base to a full hour, executes all real oracle updates/timelocks/activation/migrations/transfers and pending top-up, then obtains current snapshots. It never rewrites an exported snapshot or changes the production CLI clock. The fresh fixture reports genuine USDC/MORSE principal, a17-unit real SPL donation and a1-unit pending top-up. The retained old corpus stays unchanged. Initial fixture/oracle alignment failure, historical-clock trial and initial CLI mode RED are preserved.

To generate a new local corpus, use the copied/pinned judge/token/rewards classic-SPL SBF inputs and explicit Rust tool paths from the qualification manifest. Sample `MORSE_BONDS_FIXTURE_NOW` from the actual host at invocation; set `MORSE_BONDS_FIXTURE_OUTPUT` to a fresh file; run `cargo test -p morse-judge --features svm --test token_custody_svm fresh_readonly_bonds_v2_snapshots -- --exact --nocapture`. Then run the Node fresh CLI suite against that file with the pinned optimized CLI. Do not use a historical fixture timestamp to make a current command appear fresh. Controlled local Clock/slot, injected full-bit Pyth publications and owned distinct origins are not public finality, guardian verification, independent operators or real posted bonds.

Review, public release/dependency pins and actual release-owned network configuration remain separate gates. No production endpoints or public bond amounts are selected by this work.
